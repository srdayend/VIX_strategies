# Methodological Audit Protocol — Thesis v1

## Purpose

The thesis does not begin by improving the existing backtest. It begins by rebuilding the research logic that the backtest is supposed to represent.

The audit order is:

1. economic mechanism,
2. data construction,
3. statistical estimation,
4. hedge-ratio formalization,
5. strategy specification,
6. backtest architecture,
7. parameter governance,
8. statistical validation,
9. strategy-identity decomposition,
10. final untouched OOS evaluation.

A later stage must not be used to justify an earlier assumption.

## Research identity

The project is a **hedged VIX futures roll-down carry strategy**.

A thesis-final specification should not be called that if:
- average performance is mainly generated by the VX1 long directional leg,
- removing the carry/term-structure signal leaves the performance essentially unchanged,
- increasing the hedge ratio improves performance mainly by adding front-vol exposure rather than reducing carry-strategy tail risk.

## Research constitution

Before any new experiment:
- state the hypothesis,
- state the economic rationale,
- define the sample,
- define the primary metric,
- record the expected direction,
- record whether any OOS data has been inspected.

Do not add a rule because it improved Sharpe ex post.

The final OOS period remains untouched until the strategy specification is frozen.

## Gate 1 — Economic object

Distinguish:
- curve slope / signal,
- ex-ante static-curve roll-down,
- realized futures P&L.

Signal is not carry, and carry is not realized return.

The preferred decomposition is:

realized contract price change
= static roll-down component
+ curve-level / volatility-shock component
+ curve-shape / basis residual

The exact implementable decomposition will be finalized after inspecting the contract-level data.

## Gate 2 — Data construction

Required base grain: **contract × trade date**.

Required fields:
- contract identifier,
- settlement date,
- days to expiry,
- settlement price,
- contract family / listing type where relevant.

Checks include:
- key uniqueness,
- missing settlements,
- stale prices,
- duplicate dates,
- calendar alignment,
- monthly vs weekly contract inclusion,
- contract transitions,
- rank-series reconstruction.

M1/M2 are derived labels, not raw economic instruments.

## Gate 3 — Economic premise estimation

Re-estimate the empirical facts used by the strategy:
- contango / backwardation,
- maturity beta,
- maturity volatility,
- roll-down,
- shock sensitivity,
- VX1-spot basis,
- subperiod stability.

Use uncertainty estimates, rolling/subperiod diagnostics and dependence-robust inference where relevant.

## Gate 4 — Hedge ratio

Do not select r by backtest Sharpe.

Replace the heuristic lower/upper-band logic with a **Carry–Hedge Efficient Frontier**.

For each candidate r estimate:
- expected carry,
- uncertainty / lower confidence bound of expected carry,
- normal-period risk,
- spike conditional loss,
- Expected Shortfall,
- crisis conditional P&L.

Possible hedge benchmarks:
- minimum-variance hedge ratio,
- tail-loss / ES-minimizing hedge ratio,
- quantile/tail conditional hedge ratio.

A candidate region is frozen before final performance evaluation.

## Gate 5 — Strategy specification

Before backtesting, specify:
- signal,
- observation timestamp,
- execution timestamp,
- entry / exit,
- position sizing,
- contract selection,
- roll rule,
- rebalance rule,
- capital denominator,
- margin convention,
- costs,
- stop logic.

Another researcher should be able to implement the strategy from the specification alone.

## Gate 6 — Two-layer backtest

### Layer A: economic backtest
Primary thesis layer:
- actual contracts,
- daily settlements,
- explicit rolls,
- no unverifiable intraday stop,
- conservative costs,
- deterministic execution.

### Layer B: execution validation
Only after Layer A is frozen:
- minute/tick data,
- stop path,
- fill timing,
- bid/ask,
- slippage,
- roll-window liquidity.

Minute data is an execution-validation layer, not a substitute for a correct economic backtest.

## Gate 7 — Parameter governance

Use time-series-safe development:
- calibration/development sample,
- untouched OOS,
- expanding walk-forward robustness.

Prefer parameter plateaus and neighborhood stability over best single-point Sharpe.

If the search space becomes large, consider:
- Reality Check / SPA family,
- Deflated Sharpe Ratio,
as supplemental multiple-testing diagnostics.

## Gate 8 — Statistical validation

Beyond CAGR / Sharpe / MDD:
- annualized mean return,
- dependence-robust uncertainty,
- block bootstrap,
- Sharpe confidence interval,
- Expected Shortfall,
- drawdown duration,
- worst-k-day concentration,
- crisis conditional performance,
- subperiod dispersion.

## Gate 9 — Strategy identity

Decompose:
- short VX2 leg,
- long VX1 leg,
- combined position,
- static roll-down,
- residual curve movement,
- crisis hedge contribution.

Flag identity drift when:
- hedge leg dominates unconditional expected P&L,
- higher r mainly adds directional front-vol upside,
- the term-structure signal is not necessary for the result,
- hedge complexity raises Sharpe without reducing carry-strategy tail risk.

## Gate 10 — final OOS

Only after Gates 1–9:
- run untouched OOS,
- do not change parameters or rules afterward,
- report weak or negative results without retuning,
- freeze the final table/figure pipeline.
